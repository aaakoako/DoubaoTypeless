# 07 · 验收、证据和质量门槛

## 产品验收总表

`fixtures/acceptance.json` 包含 96 条逐项产品验收：每条有前置条件、步骤、可观察结果、执行层级、严重性、状态和证据数组。初始全部 **NOT_RUN**。本轮设计包的HTML原型测试与文档检查独立记录，不能改动此表为PASS。

## 状态定义

NOT_RUN=未执行；PASS=在记录的环境/固定提交中达到期望；FAIL=已执行但不满足；BLOCKED_NATIVE=缺Windows/真实手机/目标版本/密钥等；DEFERRED=仅已明确后置的新平台/隧道，不用于逃避R01–R10。

P0为数据丢失、错目标/重复插入、鉴权绕过、私密源图泄漏、空闲常驻等核心约束。任何P0未通过不得成为日用替换候选。P1缺项需用户明确接受，不能悄悄改规格。

## 必要测试层级

纯函数：草稿版本、Bundle冻结、图序哈希、Intent幂等、清空版本比较、恢复策略、过期AI。
协议集成：aiohttp随机回环端口、乱序重连、缺块上传、鉴权、大小/频率限制、事务失败。
手机浏览器：布局与编辑操作自动化，加真实输入法composition录制回放；模拟浏览器不能替代输入法、两指、键盘。
Windows：非激活窗口、修饰键释放、剪贴板真实图像、多应用焦点、权限、截图DPI。
端到端：真实手机准备图文→真实Cursor→人工看附件像素/文字→焦点错误召回；软件版本记录在证据里。

## 证据目录模板

```
evidence/<full-commit-sha>/<case-id>/
  environment.json
  commands.txt
  result.json
  events-redacted.jsonl
  before.png
  after.png
  recording.mp4              # 仅需要动态证明且无隐私数据时
```

环境至少：OS构建、CPU/RAM、DPI/屏幕组合、应用/浏览器版本、输入法版本、目标模型图像能力确认、前端/后端版本、网络类型。截图必须是测试数据，不拿用户真实代码或Key当证据。

result.json含case_id、status、observed、expected、started_at、commit_sha、evidence_paths；不自动生成一堆PASS。系统发键日志只能证明sent，不代替目标received。截图前后差异需真实可见，不能拿设计原型截图冒充原生实现。

## 出包前强制清单

无Key图文链路；空闲无窗口；Windows原生不抢焦点；先图后文且0次Enter；部分投递补贴；新稿不被旧回执清空；重连不重发按键；裁剪/遮挡像素验证；Key/图片不入诊断；200轮压力；干净机器启动；稳定版可回退。没有Windows包/测试环境时写明阻塞，不能称已出可用包。

## 视觉验收

图文HUD尺寸与tokens一致±2DIP；手机360/390/430宽无水平溢出；控制触控区域≥44；深色文本对比；键盘展开后所有主动作可达；画布不被浮动说明遮挡；没有额外常驻悬浮球、四标签页或管理仪表盘。录制无输入10分钟和输入→6秒静止→隐藏，单张截图不足以证明生命周期。
