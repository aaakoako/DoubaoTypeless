# DoubaoTypeless · Pocket Composer 设计与开发方案 v3

**设计日期：2026-09-18。v3 是方案版本，不是已发布应用版本。**

一句话：手机负责说、画、圈和整理图文；电脑只在需要时短暂出现，负责把这一份图文放进你选定的 Composer。不是常驻面板，不是远程桌面，也不是新的聊天客户端。

本包是新的规范入口。替代之前执行包中与本方案冲突的产品/技术/任务规定，旧任务编号不沿用。基线源码仍为 `aaakoako/DoubaoTypeless@e6b5b085d055d6f4306d486fb6d8e3cd5dfa84d5`；本轮通过 GitHub 再次查询 master 得到同一 SHA。没有改动远端仓库、真实配置或发布新版 EXE。

## 本次方向的硬边界

1. **空闲时电脑没有浮窗、吸附球或展开面板。** 托盘图标是低频入口，不等于桌面常驻窗口。
2. **手机只有一个图文输入主页面。** “截电脑 / 相册 / 白板”是添加素材动作；点击附件才进入同一个全屏编辑器。
3. **保留豆包手机输入法路径。** 不做网页录音，不模拟输入法麦克风，不假装知道用户是否正在录音。
4. **同步自动，投递显式。** 用户点手机“插入电脑”或按电脑热键，才创建插入意图；普通文本/画布同步和重连都不触发系统按键。
5. **图片先、文字后，不按 Enter。** “插入”不等于向 Agent 发起请求。
6. **上次图文可召回，目标焦点重新确认。** 不盲重试，不让部分插入造成重复附件。
7. **不等 AI。** BYOK 是手动的文字辅助；截图、画布、传图、投递、恢复全部无 Key 可用。
8. 第一轮交付范围含**轻量白板**，不再把白板整体推迟到下一版；跨平台和公网隧道仍后置。

## 交付边界

这是产品规格、技术合同和本地浏览器交互原型，不是生产系统。真实手机输入法、真实 Windows 截图/热键/焦点/剪贴板、Cursor 附件就绪检测、配对与加密、EXE 构建必须按独立验收执行。原型运行通过不能填入产品验收表。实际执行了哪些检查，以 `evidence/DELIVERY_STATUS.md` 为准。

# 00 · 产品定位、范围和完成定义

## 0. 产品不是“更小的桌面大程序”

核心体验是：**把手机变成有强语音输入和手指绘画能力的 Composer 前置输入端。** 电脑负责本地截图、可靠接收和受控投递。用户不需要理解 Bundle、Session、Revision 等工程词；界面只说“这次内容”“上次图文”“电脑已收到”。

“轻量”有三个独立含义：界面少打扰、常用动作少步骤、程序资源有限制。把按钮缩成小图标而让人找不到入口，不算轻量；无差别后台截屏和猜焦点，不算无感。

## 1. 必须保留的需求

| 编号 | 用户需求 | 本轮产品决定 | 不能替代成 |
|---|---|---|---|
| R01 | 平时不常驻，仅输入中出现 | 空闲窗口不可见；数据更新/绘画活动/用户动作短暂显示，停止活动自动隐藏 | 常驻胶囊、悬浮球、仪表盘 |
| R02 | 豆包输入法语音好用 | 普通 textarea 承接输入法，完整保留文字和组词更新 | 网页麦克风、收费 ASR |
| R03 | 手机直接画、标记 | 指绘优先；手机一个编辑器兼容标注与白板 | 要求鼠标、专业手写板 |
| R04 | 获取电脑截图 | 手机一键截已授权显示器；电脑热键区域截图；两者进入手机标注 | 手机浏览器 getDisplayMedia 去捕获远端电脑 |
| R05 | 快速裁剪、手机传图 | 相册多选；八手柄裁剪与自由框选；恢复原始裁剪 | 上传后必须经过一堆导出设置 |
| R06 | 快速白板与实用工具 | 第一轮含白板、3 类笔刷、形状、编号、文本、撤销、选择移动 | 专业绘画软件、无限画布 |
| R07 | 图文让多模态模型理解修改意图 | 编号标记 + 对应说明；已处理图片 + 用户原文按固定顺序投递 | AI 自动臆造需求、自动附整屏原图 |
| R08 | 一键先图后文 | 通过已验证适配器自动逐图等待，再插入文字，不发送 Enter | 盲等 300ms 后直接连续 Ctrl+V |
| R09 | 目标不对时再唤起重试 | 召回最近实际投递过的不可变快照；重新选目标；部分投递可补贴 | 沿用旧 HWND 或每次重贴所有图 |
| R10 | BYOK / 易用 / 简单引导 | 3 步入门，无 Key 完整图文链路；一个手动 AI 配置 | 双模型必配、自动学习队列 |
| R11 | 以后 macOS、Linux、隧道 | 接口隔离，本轮不发布这些功能入口 | 承诺换 UI 就自动全平台可用 |

## 2. 冻结的产品决定

D01：界面视觉名仍用 DoubaoTypeless；Pocket Composer 是设计说明，不在本轮改项目名、域名或商标。
D02：工作态始终一个草稿；可以有最近记录，但不做看板、文件夹、标签和多草稿项目管理。
D03：首批重点验证 **Windows + Android 浏览器 + 豆包输入法 + Cursor Agent/Composer**。这是根据使用场景确定的验收优先级，不是宣称已支持某个 Cursor 版本。Windows 11 为主测；其他系统版本记录能力差异。
D04：保留正常纯文字路径的速度；用户没有图时不显示图片占位条，不必点“打包/发送到电脑/确认”三次。
D05：文本输入增量同步，图片编辑在本地流畅完成，按“完成”才生成可投递图片；画布中未完成的笔画不自动插入。
D06：一份内容最多 6 张已处理图片、文字 UTF-8 64KiB。超出限额只禁本次新增或提示拆分，不静默删图/截断。
D07：“插入电脑”建立一次固定快照；用户之后继续说话或绘画属于新版本，不能混进已经执行中的插入。
D08：正常连接、同步、心跳不反复弹通知；失败在手机持续可见，电脑仅短暂提示，不为错误强制常驻。
D09：默认不抓目标应用全文、不自动截图识别焦点、不后台监听剪贴板正文。定位只使用必要的窗口/可访问性元数据。
D10：插入按钮只承诺“放入输入框”；最终发送给模型由用户在目标应用确认。

## 3. 本轮完整交付与内部切片

完整候选必须含 R01–R10；不能用“先做了文本，白板以后再说”冒充整轮完成。内部按风险递增交付，不按猜测日历排期。

| 里程碑 | 必须能体验的结果 | 退出门槛 |
|---|---|---|
| G0 技术风险确认 | 非激活小浮窗、手机一笔、真实 Cursor 两张图片后文字、重新聚焦再投递样板 | 有 Windows+手机实测；未知项不能扩大为承诺 |
| G1 纯文字日用不倒退 | 不等 AI、不常驻、丢焦点不丢字、旧热键可用、配对与版本同步 | 旧路径回归和新浮窗状态用例通过 |
| G2 手机图文闭环 | 相册、电脑截图、裁剪、基础标注、图文投递、上次召回 | 图像真字节进入目标、无重复发键、裁剪不泄露区域 |
| G3 完整表达工具 | 白板、3 种笔刷、形状/编号/文字、撤销/移动、BYOK和引导设置 | 所有范围需求有可追溯用例与视觉证据 |
| G4 独立候选 | 便携 Windows 包、校验值、依赖锁定、迁移与回退文档 | 干净机器实测 + 人类高强度使用回归 |

## 4. 工作流的动作预算（验收目标，不是当前实测）

纯语音：完成首次配对后，手机点输入框说话 → 电脑 Alt+I。新增菜单动作数为零。
截图修改：手机点“截电脑” → 在图上画 → 完成 → 插入电脑。裁剪只在需要时增加一个动作。
白板表达：点“白板” → 画 → 完成 → 说说明 → 插入电脑。
焦点修复：点正确 Composer → Alt+Shift+I。已确认无任何投递时直接重跑；部分/未知结果只加一次恢复方式确认。

## 5. 不做清单

不做网页端语音识别、不做远程鼠标键盘、不做持续屏幕流、不做模型聊天客户端、不自动按 Enter、不做自动提交代码、不自动 OCR/分析截图、不默认 AI 改写、不做云同步、协作白板、无限画布、动画笔刷、模板商城。首次隧道与新平台必须单独 ADR、安全评审和实测。

# 01 · 交互结构、浮窗生命周期与视觉规格

本节尺寸单位：桌面为逻辑像素 DIP，手机为 CSS px；截图中的浏览器原型演示外框不属于产品。颜色、尺寸、动效的机器可读值在 `design/tokens.json`。

## 1. 视觉方向：安静的工具，而不是 AI 控制台

手机浅色纸面、深墨正文、一个克制的青绿色主动作；深色模式使用深灰纸面而不是纯黑全屏。画布标注色独立于品牌色：珊瑚红用于指出问题，蓝色用于结构，琥珀色用于高亮。颜色只帮助阅读，不预置“红色必定删除”的业务语义。

不使用大面积渐变、持续发光、假音量波形、玻璃模糊、巨型品牌区、卡片套卡片。工具图标统一线性风格，手机保留短标签。没有内容时允许留白，但不占满说明文案。

| 参数 | 固定值/规则 |
|---|---|
| 主色 | #167D71；白底按钮文字与背景组合须重新测对比度 |
| 浅色 | 背景 #F5F5F1；面板 #FFFFFF；正文 #1D2826；次文 #63716D；边线 #DBE2DE |
| 深色 | 背景 #141C1B；面板 #202B29；正文 #EAF0ED；次文 #A8B7B1 |
| 警告/失败 | 提示底 #FFF3DF / #FFF0ED；必须同时显示图标与文字，不只换红灯 |
| 字体 | 手机 system-ui；Windows Segoe UI / Microsoft YaHei UI；不打包系统字体 |
| 字号 | 主文 16px、辅助 12–13px、手机页标题 18px、桌面 HUD 13px |
| 间距 | 4/8/12/16/24；手机外边距16；画布全屏模式外边距8 |
| 圆角 | 控件10、手机卡片16、HUD16；整页不统一胶囊化 |
| 触控目标 | 手机至少44×44；画布裁剪手柄命中区44，视觉小圆可为10 |
| 动效 | 出现140ms淡入+4px，消失120ms；禁循环弹跳，减少动态效果时0ms |
| 焦点 | 键盘焦点环2px；不要移除 outline；文本最低4.5:1，非文字交互目标3:1作为验收目标 |

## 2. 桌面不是主界面：只有 5 种按需表面

| 表面 | 出现条件 | 内容 | 退出 |
|---|---|---|---|
| 输入 HUD | 真正文本变化/图片加入/用户绘画活动 | 输入中、正文末两行、图片数、插入/更多 | 6s无有效活动自动隐藏；隐藏不清稿 |
| 紧凑活动条 | 连续画布操作、图像传输 | 正在标记/图片1/2传输中 | 6s无活动隐藏；不播放假录音波形 |
| 图文详情 | 用户点更多/按Ctrl+Shift+U | 当前或上次缩略图、全文、插入/召回 | Esc仅在详情有焦点时关闭，保留稿 |
| 截图区 | 用户明确电脑截图热键 | 选显示器/区域，尺寸和取消 | 选择完或Esc退出；不长驻 |
| 设置/首次引导 | 首次启动、托盘明确选择 | 连接、快捷键、隐私、可选AI | 关闭后回到无窗口 |

输入 HUD：纯文 `360×88`；有附件 `360×132`；上传/绘画活动条 `252×44`。图文详情 `420×320`，可调整但默认不超过 `480×480`。低频设置 `560×600` 可滚动，无常驻侧栏仪表盘。

默认锚点：工作区底部居中，上距任务栏16 DIP。记住用户拖动位置并限定在当前工作区；不跟着光标四处漂移。两行正文尾部展示，不随长文不停增高。缩略图最多显示3张+余量。HUD不是文本编辑器；编辑全文需显式打开详情。

## 3. 浮窗状态机（不可由 UI 各自猜测）

| 状态 | 入口事件 | 可见/焦点 | 行为/文案 | 退出条件 |
|---|---|---|---|---|
| HIDDEN | 启动完成、超时、成功收起 | 不可见、无任务栏按钮 | 草稿/最近快照仍在本机 | 有效编辑活动或显式命令 |
| RECEIVING | text.changed / asset.added / editor.activity | 非激活HUD | 输入中；两行文字/图片数；Alt+I | 无活动6s→HIDDEN；插入→PREPARING |
| PREPARING | 本地hotkey或有效手机intent | 非激活HUD | 正在准备图片1/2；取消 | 全部资产校验→INSERTING；失败→ATTENTION |
| INSERTING | 目标已验证且修饰键已释放 | 非激活HUD | 正在插图1/2/正在插入文字 | 完成→RESULT；目标改变→ATTENTION |
| RESULT | 本次投递步骤结束 | 显示900ms | 适配器观察到结果：“已放入输入框 · 未发送”；未确认：“已尝试插入 · 可召回” | 900ms→HIDDEN，数据不删除 |
| ATTENTION | 焦点未知/部分完成/权限失败 | 短暂非激活提示 | 点目标输入框，再按Alt+Shift+I；或图已尝试，文字未贴 | 8s→HIDDEN，手机保留状态与操作；显式召回→DETAIL |
| DETAIL | Ctrl+Shift+U/更多 | 用户主动展开可激活 | 完整预览/恢复选择 | 关闭→HIDDEN，绝不删除 |

有效活动：文本字节改变、附件改变、指针真实绘画/拖动/裁剪。心跳、连线、旧消息重放、模型后台状态不算。绘画活动每2s最多一次，不把每个点传上网。新活动可重新显示，同一段不得反复开关抖动。窗口出入不触发重新捕获目标。

全屏演示/游戏默认不自动显 HUD；明确热键可显示。系统锁屏禁止插入与截图，回到桌面不执行排队的远程动作。失联且没有进行中的草稿/操作，不在电脑弹窗。

**Esc不能做全局吞键。** HUD不夺焦点，外部编辑器的Esc仍属于外部程序。只有详情/截图/设置自己有焦点时Esc关闭相应表面。隐藏快捷键用Ctrl+Shift+U切换。

## 4. 手机主页面：一个 Composer

顶部52px：左为连接圆点+电脑名，右为最近记录和更多；配对异常时圆点旁显示一句可操作的提示。主内容为按顺序排列的图片附件横条（没有图就没有这一块）+普通textarea。底部靠近拇指位置：`截电脑`、`相册`、`白板`；下方一个主按钮`插入电脑`，旁显示电脑已收到/待同步。

不要新增“发送”标签。图片编辑完成回到同一个草稿，图片顺序就是投递顺序；编号为1…6。多图通过长按拖动排序，同时提供“左移/右移”作为无障碍替代；删除有5s撤销。

图片附件角标可以选“现状/参考/草图”，默认按来源展示“截图/图片/白板”，只是辅助描述。图注默认不强制填写。编号标记后的文字说明可一键插入到正文光标处，插入前显示生成文本预览；不能自动改用户的语音全文。

主按钮状态：空内容→禁用；编辑画布未完成→要求先完成，不偷偷导出；上传中→点击可进入“准备中”且锁定当前快照；已同步→插入电脑；失联→“等待连接”，草稿本地保存，不自动排队远程按键；未知焦点→“点电脑输入框后重试”。纯文无需一次“发送到电脑”加一次“插入电脑”，点击一个动作即可快照并提交。

文字输入保留input/composition事件，不对真实值使用trim/strip，只用其判断是否全空。手机不会控制豆包麦克风或显示采集波形。`输入中`意味着正在收到文字变化，不意味着我们知道音频录音状态。

## 5. 键盘与画布切换

进入编辑器时显式收起键盘；完成编辑回主页面时不程序性强拉键盘，用户点文字区域恢复。画布编辑内点“补充说明”打开底部文字抽屉，可继续用输入法语音；不需要回首页再返回。利用visualViewport测键盘遮挡、safe-area-inset-bottom留底部区域；回调节流到一帧，不能每次键盘变化重建画布。[S04]

不承诺网页在手机锁屏后保持WebSocket。恢复前台先检查会话和草稿差异，补传最新快照；不能重放投递或截图命令。

## 6. 新手引导与设置

首次桌面引导仅3步：①配对手机（二维码+可信网络说明）；②手机输入一行并验证电脑收到；③在明确的练习输入框试文字，再可选试一张示例图。完成后清楚说明Alt+I、Alt+Shift+I、Ctrl+Shift+U，并回到桌面无窗口。白板和AI不是强制引导步骤。

手机首次进入只有输入框下的一句提示“点这里，用手机输入法语音；也能添图画一画”，成功输入后不再重复。截图权限只在首次截图时解释并批准目标显示器，不在启动时索要所有权限。

设置折叠分组：连接设备；快捷键；截图授权；隐私/最近记录；可选AI；诊断。顶部不出现CPU、token用量、模型榜单。记住设备/自启动由用户明确选择，不能以无感为名静默授权。

## 7. 默认热键

| 动作 | 建议默认 | 语义 |
|---|---|---|
| 插入当前内容 | Alt+I，继承旧习惯 | 以此刻前台目标和当前已完成版本建意图 |
| 召回并重试上次 | Alt+Shift+I | 读取last_attempt_bundle；重新采集目标；必要时恢复方式确认 |
| 展开/隐藏详情 | Ctrl+Shift+U，继承旧习惯 | 当前非空稿优先，否则上次快照；不自动插入 |
| 区域截图给手机 | Alt+Shift+S，新建议可改 | 不自动投递，仅截图并打开手机标注 |

冲突必须用平台注册结果反馈并提供改键，不能宣称检测了所有外部软件。没有上次快照时Alt+Shift+I只短暂提示，不拿当前草稿冒充上次。

逐控件尺寸、首次授权、恢复选择、BYOK与错误文案补充见 `spec/10_COMPONENT_DETAILS.md`；静态状态板在 `design/STATE_BOARDS.html`。

# 02 · 手机截图、传图、裁剪、标注与轻量白板

## 1. 三个入口，一个编辑器

“截电脑”得到授权显示器/窗口的瞬时截图；“相册”选本机图片；“白板”新建空白画布。入口不同，进入后都是同一编辑器：顶栏 返回/标题/撤销/重做/完成，中间画布，底部两级工具栏。没有专门白板账号、文件项目、团队空间或复杂图层列表。

手机截图入口默认复用用户上次批准的显示器：点一次获取当前画面并打开编辑器；长按或箭头可切换显示器/窗口。不能默认截所有屏幕。电脑区域热键弹出选择罩，用户用鼠标选择只是可选快路；不用鼠标时，手机截整块已授权显示器再用手指裁剪同样完整可用。

**浏览器getDisplayMedia只用于它所在设备的屏幕获取，并有安全上下文/用户动作限制；不能让手机网页凭它取得另一台电脑的桌面。** 本方案通过电脑原生CaptureService执行用户授权的截图请求。[S05]

## 2. 截图权限与时序

首次手机请求时，桌面短暂展示主动授权窗：“允许这台手机截取显示器1？仅你点截图时截取，不持续分享。”选择一次/本次会话持续允许/拒绝。系统锁屏、敏感或受保护窗口、设备被撤销时拒绝并给手机明确反馈。

`capture.request(id, scope_id)`必须来自授权设备且由明确点击发起；本次请求标记一次性，15s过期，重连不补执行。每台设备一次并发，最快2s一张。执行前临时隐藏本应用HUD/选择罩，等待系统合成下一帧后截取，并在Windows实测不会把自家浮窗截进去。截图范围以物理像素/显示器DPI为准，不把DIP直接当像素。

截图完成返回唯一asset_id与尺寸、哈希，图像走带会话鉴权的二进制HTTP端点；不把Base64图片塞进WebSocket文本帧，不生成无鉴权公开图片URL。手机收到相应请求结果自动进入标注；意外或过期结果只显示一条“截图已收到”待选择，不打断正在写的另一张图。

## 3. 首版实用工具集

| 工具 | 交互/参数 | 完成结果 |
|---|---|---|
| 圆头笔 | 实线；细/中/粗；单指画，起落圆头 | 可选择移动/删除的笔画对象 |
| 记号笔 | 宽、全不透明、笔端圆头；用于涂块和草图 | 不能称为可靠隐私遮挡（需遮挡工具） |
| 荧光笔 | 25%不透明度，乘色视觉；一笔一次alpha合成避免来回更黑 | 强调但保留底图可读性 |
| 直线/箭头 | 拖起终点；箭头端头长度与线宽相关 | 对象可拖端点，默认单向箭头 |
| 矩形/圆角矩形/椭圆 | 按下定起点，拖动定包围框 | 可选填充，默认无填充 |
| 编号钉 | 点一下创建1/2/3…；跟图ID关联 | 说明抽屉列出①②③，导出显示编号 |
| 文字 | 点位置开系统键盘，文本框排版，不做手写识别 | 字体3档，支持多行/中英文 |

| 遮挡 | 不透明矩形，最终导出在像素上彻底替换 | 默认黑；不可只blur或像素化后说已安全脱敏 |
| 裁剪 | 自由框选+8手柄；原比例/1:1/16:9/自由 | 非破坏编辑，导出只含裁剪范围 |
| 移动画布 | 两指平移/捏合；另有显式手形工具 | 不改变图片/对象真实坐标 |

工具常显6个：笔、箭头、框、编号、裁剪、更多。点笔弹出3种笔刷与粗细；更多含椭圆/直线/文字/橡皮/选择/遮挡/手形，不把十几个图标压在一行。最近使用颜色3个+5色基础板。设置颜色只影响新对象和当前被选择对象，不重染已有全部笔画。

不需要压感也能完成全部工作。检测到真实pen事件和压力后可作为圆头笔选项，缺少压力时固定宽；不宣称手指触控能提供准确压力。[S03]

## 4. 手指操作细节

单指绘画；第二根手指接触后结束并撤销尚未提交的临时笔画，切入平移/缩放，不能留下两指开始时的短墨点。第二指抬起后本轮手势不恢复绘画，等全部离开再开始下一笔。

允许触点离开画布仍结束当前笔：使用pointer capture；处理pointercancel，提交完整已完成部分或取消整笔策略固定为“取消当前未完成笔，不影响历史”。touch-action:none仅用于画布，页面其他区域仍正常滚动；不全页面禁缩放。[S03]

默认画笔不吸附，不把圈绘自动变成形状。图形可开启靠近水平/垂直的轻吸附；触控绘图输入先实时显示原始位置，落笔结束后做低强度平滑，不把用户的结构猜成“更漂亮”的另一种意思。

缩放25%–400%，双击空白适配画面；有快捷“适配”。缩放后绘画坐标必须逆变换到原始文档空间，导出与屏幕DPR无关。不能直接把clientX/clientY存成图像像素位置。

## 5. 裁剪规则（必须实现真实裁剪，不是框一块装饰）

源图坐标系固定为宽W、高H；标注坐标也在源图坐标系。裁剪为`{x,y,width,height}`矩形，允许调整/取消/恢复全图，不删除源图和标注对象。显示时clip场景，导出时新建crop.width×crop.height像素画布，按(-x,-y)平移绘制合成结果，之后再按导出限额缩放。

手柄最小可点击44px；选框最小64×64源像素；接近边界显示放大镜可作为后续增强，首版至少显示实时尺寸和双指放大再拖手柄。取消裁剪恢复进入裁剪前矩形；完成裁剪进入同一个标注编辑器，不自动结束附件编辑。

裁剪、旋转（首版只90度）、遮挡、画笔、图片位置变化都进入同一Undo历史。原型若只实现部分，必须标在evidence，不允许当成产品完成。

## 6. 白板不是无限画布

默认1600×1000浅色白板，可选竖版1000×1600、正方形1200×1200。点状网格只作编辑辅助，默认不导出。工具与标注完全复用。

首版提供一个“线框图形”折叠组：矩形容器、按钮、文本线、图片占位。它们是普通可编辑对象组合，不是可运行UI组件。可放入参考图片但不会自动把图片变成设计图。插入组后默认选择可移动，文字可改。

“导出可见内容”按所有对象外接框+48px留白计算，仅在用户确认时切换；默认白板整画布导出，以避免小部分被无意裁掉。空白白板不得加入附件。

## 7. 让模型更容易理解，而不是自动替人写需求

建议工作法：在问题位置放①，在右侧画一个改后草图②；说明写“图1①是当前按钮区域，按②布局调整，其他区域保持不变”。编号明确指向具体图，图序改变时说明引用用稳定asset_id绑定，重新生成图序说明前预览。

默认不加系统提示词、不上传原图、不重写自然语言。用户点击“附上标记说明”时在正文后添加可编辑的短段：

```
图片说明：
图1（截图标注）：① 需要修改的按钮区域。
图2（白板草图）：目标布局，文字大小仅作示意。
```

仅使用用户输入的注释与素材角色；没有注释不凭空描述图。图片含代码/UI文字时默认PNG以保清晰；相册照片可选JPEG，导出不保留EXIF、定位或未使用的原始图层。

## 8. 图像限制与性能

导入允许PNG/JPEG/WebP；HEIC支持需另选解码组件并过真机门槛，未支持时提示先转格式；SVG首版不导入，防止活动内容及外链。客户端先读尺寸，单张源图上限48MP、文件20MiB；过大不在主线程无约束解码。首版超限明确提示先裁剪/压缩，不自动将高分辨率图不可逆缩小后覆盖原文件。

发送默认长边2560px、单图8MiB、最多6张且合计24MiB（均为产品预算非模型官方限制）。高清选项长边4096但仍8MiB上限，超限提示缩图/裁剪；可用适配器进一步限制，不借“自动兼容”静默丢图。保存的源图与导出图分离，发送预览可检查文字可读性。

画布每次requestAnimationFrame最多渲染一次；导出耗时移到worker/异步队列，有进度和取消；编辑空闲不循环requestAnimationFrame。单画布最多500对象/50000采样点；超限前提示简化/另起草图，自动丢笔画禁止。撤销50步或8MiB命令内存，超过时只丢最旧Undo能力，不丢当前图。

同一草稿仅一台手机拥有编辑写租约；新设备接管需明确确认。手机在IndexedDB存源图、场景JSON和草稿，持久化可能被浏览器回收，界面不得承诺永久保存。长时间离开前可“导出本次图文”。普通LAN HTTP下不假设Service Worker/系统剪贴板API可用。[S06]

# 03 · 先图后文投递、焦点确认和上次图文恢复

## 1. 三件事不能混为一谈

**收到内容**：电脑已校验并持久化草稿/图片；不意味着外部应用收到了。
**执行插入**：本工具发出了系统粘贴输入；不意味着目标应用接收了图片、上传完成或光标正确。
**观察到结果**：某个已验证适配器在目标Composer中观察到预期附件/文字变化；不意味着模型收到消息，因为本工具不按发送键。

Windows的SetForegroundWindow可能被系统拒绝；SendInput返回的是注入事件数，并受权限等级等限制。所以不能把窗口句柄存在、一次API返回正常或固定等待时间当成插入成功证据。[S01][S02]

## 2. 不可变快照与两个“最近”指针

当前草稿Draft可连续变化；按插入时生成不可变DeliveryBundle，包含当时文字原字节、已处理图片的有序列表和哈希。投递步骤从此只读Bundle，不能再读取current_text/latest_image这样的共享可变变量。

`last_attempt_bundle_id`在首次实际尝试或明确提交的投递意图被接纳时设置，供“上次图文”召回；`last_confirmed_bundle_id`仅在有目标观测或用户确认时更新。新输入只改草稿，不覆盖这两个指针。按重试是新Attempt，仍引用原Bundle。编辑上次内容必须复制为新Draft，不能修改已经发生的记录。

首版最近记录仅20份/24小时/合计256MiB，以先到上限为准；最近一次未完成或失败快照最多保留24小时并在清理前提示，空间不足时停止新截图/投递，不偷偷删唯一恢复副本。用户可立即删除，关闭历史时会话内仍可召回，重启后明确不可恢复。UI不把记录叫任务管理中心。

## 3. 如何选择目标

### 电脑快捷键（首选最快路径）

用户在目标Composer点入光标，按Alt+I。**在显示任何本工具表面之前**采集前台窗口、PID、进程启动时间、可访问性焦点元素与Composer适配器标识。等待用户释放Alt/Shift等修饰键，再开始插入。每一步之前重新验证目标仍相同且可编辑。

### 点击浮窗

HUD非激活，点击主按钮原则上不夺键盘焦点；Qt/Win32交互需原生实测。若当前打开的是可编辑详情，则使用进入详情前保存的明确目标，尝试恢复后重新核验。不能直接拿“最近某次窗口”代替目标输入框。

### 点击手机“插入电脑”

来自已批准设备的显式intent，仅在本次会话允许手机插入、当前电脑前台正处于已验证Composer、无锁屏和无其他插入时执行。已知目标不可编辑或焦点在代码区/终端/密码框时返回NEEDS_TARGET，不自动猜鼠标坐标，不偷偷切窗口。

可选“找回最近目标”只在用户显式选择时恢复已绑定Composer，且恢复后必须重新验证；不作为后台同步的默认动作。

### 不认识的输入框

普通文本程序可以在用户桌面热键明确授权下走通用文本粘贴，结果为“已尝试”。图文的一键完整流程必须有目标适配证据。仅识别进程名为Cursor不够，同一窗口可能同时包含代码编辑器、终端和Composer。

## 4. 自动投递状态机

```
READY → FREEZE → WAIT_ASSETS → CHECK_TARGET → WAIT_MODIFIERS_UP
  → PUT_IMAGE_1 → WAIT_IMAGE_1_ACCEPTED
  → ... → PUT_IMAGE_N → WAIT_IMAGE_N_ACCEPTED
  → CHECK_TARGET_AGAIN → PUT_TEXT → OBSERVE_RESULT
  → CONFIRMED / UNKNOWN / PARTIAL / NO_STEPS / CANCELLED
```

每张图片只在轮到它时写系统剪贴板；优先通过Qt QMimeData/QImage，让原生图像格式可用，Windows PNG/CF_DIB/CF_DIBV5能力由原生样板实测确认。不能只写图片路径、Data URL或文件名就宣称贴入了图片。[S07][S08]

持久化结果统一为RUNNING（进行中）、NO_STEPS（一个粘贴步骤也未发出）、PARTIAL（已执行部分）、UNKNOWN（接收不明）、CONFIRMED（已观察到接收）、CANCELLED（用户取消）。界面“未确认/已尝试”对应UNKNOWN，禁止另造UNCONFIRMED或把UNKNOWN显示为成功。错误原因另以error_code返回，不改变步骤事实。

步骤必须记录before-send / sent / observed三种边界：向OS发键前写日志；系统事件发出后持久化sent；有观测后写observed。程序在sent附近崩溃，恢复结果UNKNOWN且不自动再发。系统输入不可撤回，不能保证跨进程严格exactly-once。

先检查焦点，再准备剪贴板，再次验证焦点，再发Ctrl+V。短小的焦点竞争窗口仍可能存在，文档不能宣称彻底消灭；发现窗口/焦点变化立即停剩余步骤并保留包。不得用系统全局阻塞鼠标键盘作为“可靠性”方案。

剪贴板被其他应用占用：100/200/400ms共3次尝试打开，耗尽后停止且不丢数据。一次Attempt持有本应用的ClipboardLease；只阻止本应用其他写入，不声称独占整个系统。通过剪贴板序列号检测用户中途复制了新内容；检测到非本程序修改，立即暂停，不把用户刚复制的内容覆盖回去。

## 5. 图片就绪是硬问题，不能用假定时解决

每个适配器实现`classify_focus`、`begin_observation`、`observe_image`、`observe_text`；须记录目标应用版本与UI特征。不使用模型截图推理识别焦点，默认不运行OCR，不开启浏览器远程调试端口。

已验证适配器：能读取附件占位/加载状态，确认本次对应的新附件进入可用状态，再处理下一张。观察超时预算单图15s、完整尝试60s；达到预算停止，不自动再贴同一张。非稳定UI树返回UNKNOWN，而不是猜成功。

通用兼容模式：没有可观察附件能力，贴一张后在手机/短浮窗提示“图已尝试贴入，请确认”；用户确认后继续。可另外提供“打开图片所在文件夹/复制当前图片/复制文字”。**这种降级不是完整一键模式，不能填一键验收通过。** 首轮Cursor验收若拿不到可靠附件就绪信息，保留半自动试用且标记G0/G2未闭合；不能拿通用模式冒充全自动已实现。

截图/图像可能包含无法识别的文字、模型可能没有图像能力，属于目标产品/模型选择约束。首轮适配测试需人工选择一个当前支持图像的目标模型并记录名称；本工具不根据模型名猜能力或偷偷切换模型。

## 6. 焦点错了，正确的“重发”是什么

默认快捷键Alt+Shift+I：召回上次Bundle，**以现在选中的目标**建立Attempt。不会拿新草稿代替上次，也不会继续使用旧焦点。

| 上次结果/当前目标 | 默认恢复 | 为什么 |
|---|---|---|
| 没有任何步骤sent | 重新确认目标后完整重跑 | 没有重复附件风险 |
| 附件均observed，文本尚未sent，仍是同一Composer/同一输入文档 | “只补文字” | 避免同图重复 |
| 已知只收了前k张，目标仍相同且状态可观察 | “从第k+1张继续” | 仅在证据充分时使用 |
| 部分/未知结果，或目标身份改变 | 展示一次恢复选择：完整重贴 / 只贴文字 / 取消 | 系统不能猜哪部分在目标里 |
| 之前确认完成，又在同一输入框重试 | 警告可能重复；用户选择“已清空或换新输入框，完整重贴” | 禁止把重试当作无副作用动作 |
| 图片/正文已过期或被删除 | 明确“上次图片已清理”，不拼凑只有文字的假原包 | 不制造与上次不同的材料 |

完整重贴不会自动Ctrl+A、Delete、Ctrl+Z清理目标，因为可能删掉用户原有的文字和附件。恢复选择应展示上次图数、正文首行、步骤结果，不要求用户读技术日志。首轮可以不做历史搜索，只保留最近20条轻列表和召回入口。

## 7. 防连按、重连和重复命令

每个intent带客户端生成的UUID；同一intent重发只返回已有Attempt，不再执行。服务端保存去重状态24小时，重启后running统一恢复为UNKNOWN。一次只运行一个Attempt；第二个新intent返回BUSY，不排队在焦点已经改变后执行。

物理热键keydown重复不得生成新intent，等keyup后才能再次触发。同一Bundle+目标在2秒内第二次请求显示正在处理，不启动第二份。用户主动重试生成新intent且履行恢复确认。

手机断线重连只补草稿/资产，不重发旧insert.intent/capture.request。intent有效期10秒由服务端会话颁发的短时nonce及单调时间校验，不依赖手机墙钟。页面重载后的旧pending intent显示结果查询，不再次发键。

## 8. 插入完成之后，不急着毁掉证据

确认完成时：电脑900ms后隐藏；手机底部短暂显示“已放入输入框 · 未发送”，将匹配版本归档并进入空的新稿。存在更新版本时不能清空，应留在新的Draft并标“上一份已插入”。只用设备ID+DraftID+Epoch+Revision+BundleHash全部相等才允许将当前版本移入最近记录。

未确认/部分结果时：手机保留原稿和“重试/查看图文”，不自动变空。电脑短暂提示后隐藏，用户仍可召回。图片像素和文字原文都须保留，不能只保留路径且源文件已清理。

默认剪贴板最终保留最后投递文字；图片-only则保留最后一张图。在第一次引导说明这点。原有“剪贴板保护”配置迁移为清晰选项，不能承诺保存所有复杂应用剪贴板格式；只有确认目标完成且剪贴板仍属于本次操作时，才可尝试恢复受支持的原格式。

# 04 · 工程拆分、数据模型和协议合同

## 1. 技术选择与迁移策略

**桌面：Python + PySide6 Widgets。手机：TypeScript + Vite + Konva。网络：保留aiohttp。持久化：SQLite + 受限本地资产目录。** 不引入Electron、Qt WebEngine、React、大型白板SDK或Node后台服务。Node只在构建时把手机资源编成静态文件，由Python提供。

这是针对“桌面极简、复杂交互在手机”的新范围调整，不是宣称Widgets一定比QML更省内存。PySide6 Widgets提供原生窗口/剪贴板/屏幕接口；手机Konva提供可编辑图形与绘制基础，移动手势仍需自行按规格实现。[S07][S09][S10]

保留CustomTkinter作为G0未通过时的短期基线，**不是同时维护两套新UI**。G0先原生验证，成功后迁移生产入口；不做一次性全工程改名。版本必须在G0实际安装/运行后锁定，文档不给未验证的“最新精确依赖版本”。

Qt GUI/剪贴板/窗口操作在主线程；aiohttp在一个有生命周期管理的后台asyncio线程；所有跨线程事件通过有类型的Qt Signal/queued connection。OS观察/图片处理放工作队列，UI不能同步等待网络或导出。退出顺序：拒绝新intent→停止插入→释放修饰键→关闭WS→提交DB→停止托盘/线程。

## 3. 核心对象

| 对象 | 关键字段 | 不变性/目的 |
|---|---|---|
| DeviceSession | device_id、session_id、capabilities、expiry、last_seen | 凭据只在传输层，业务日志不可含token |
| Draft | draft_id、epoch、revision、editor_device_id、text、ordered_asset_refs | 手机拥有写租约；每次已提交文本/附件版本+1 |
| ImageDocument | asset_id、source_size、crop、objects、undo_version | 手机可编辑场景；原始坐标，不保存DOM |
| RenderedAsset | asset_id、render_revision、sha256、mime、size、width、height | 二进制校验完成后才可引用，文件路径由服务端生成 |
| DeliveryBundle | bundle_id、draft identity、text、ordered_assets、manifest_hash | 冻结后只读；重试复用同一份 |
| TargetContext | HWND、PID、process_start、adapter、focus identity、observed_at | 内存态短命；重试重新采集，日志不存敏感窗口标题 |
| InsertIntent | intent_id、bundle_id、session_nonce、trigger、recovery_mode | 显式用户动作；一次性、10秒有效 |

Manifest哈希：UTF-8编码的规范化JSON（键排序、无多余空白、明确Unicode和换行策略）；文字不做NFKC或trim。哈希覆盖图片顺序、渲染版本和每张图片实际SHA256。本包固定算法见contracts/README.md，金标准字节见fixtures/manifest.canonical.json；不能Python/JS各凭默认JSON序列化。

## 4. WebSocket只传小消息，HTTP传图片

协商子协议`dt.v3`。所有WS消息包含`protocol=3,type,message_id,session_id`；连接凭据不写在URL查询串。服务端从已鉴权连接赋值device_id，拒绝客户端冒充。单帧最大256KiB、文字64KiB，类型未知返回可理解错误而不是尝试执行。

| 消息 | 方向 | 语义/必需字段 | 是否可重复 |
|---|---|---|---|
| session.hello / ready | 双向 | 版本、能力、server_boot_id、已存draft游标 | 可，不能触发插入 |
| draft.update | 手机→电脑 | draft_id/epoch/revision/text/asset_refs、is_composing | 最新完整快照；旧版本忽略，同版不同hash拒绝 |
| draft.ack | 电脑→手机 | 同版hash、durable=true/false、缺少asset列表 | 收到ACK才能显示电脑已收到 |
| editor.activity | 手机→电脑 | draft_id、kind、不含笔画正文 | 2秒最多一次，唤醒HUD但不代表数据持久化 |
| asset.ready | 电脑→手机 | id/render_rev/hash | 图片校验并保存完成 |
| capture.request / result | 双向 | request_id、授权scope、结果asset引用 | 一次性，15s过期，无自动重放 |
| bundle.commit / ready | 双向 | frozen manifest，服务端验证资产完整 | 同manifest幂等；缺图拒绝ready |
| insert.intent / attempt.status | 双向 | 一次性意图；步骤阶段与结果 | 重传只查已有状态 |
| draft.archive | 电脑→来源设备 | 匹配draft identity+bundle hash | 仅匹配稿归档，绝不广播无条件clear |
| ping / pong | 双向 | 序列/时间 | 心跳不得导致HUD出现 |

文本更新防抖80ms（上限每秒15次），compositionend补发同文最终标记，客户端不把停顿当成“麦克风停止”。服务端流控超限合并最新草稿，不能合并/重排不同insert.intent。最终提交时发送完整文字，防止遗漏尚未发出的80ms尾巴。

## 5. 二进制资产HTTP接口

```
POST /v3/assets/init
PUT  /v3/assets/{upload_id}/chunks/{index}
POST /v3/assets/{upload_id}/complete
GET  /v3/assets/{asset_id}/render/{revision}
DELETE /v3/assets/uploads/{upload_id}
```

init带期望MIME、总bytes、SHA256和图像尺寸；服务端分配不可猜的upload_id。块大小1MiB，最多并发2个；先stream写临时文件并累计大小再校验，不一次读入无上限body。complete核对总哈希、魔数、解码尺寸和实际像素预算，失败删除临时文件并返回明确错误；只有完成后写入资产表。

断点续传按缺失块列表恢复；旧render_revision上传结束不能替换新图。下载要求同设备/会话授权与所属草稿，不能知道asset_id就任意取图；响应no-store、禁止外部Origin。HTTP鉴权方式、Cookie/CSRF和WS鉴权详见安全章节；文件名永远不当作路径。

## 6. 数据落地与一致性

SQLite保存devices、drafts、bundles、bundle_assets、attempts、attempt_steps、migrations；图像存本应用数据目录随机/哈希文件名。先写临时资产→校验→原子rename→DB事务挂引用；失败不得发送durable ACK。垃圾回收只清理无引用且超过TTL的资产，正在导出/上传/Attempt引用的资产不得清理。

需要重启可召回时，图文快照、步骤和图像必须持久化一致。隐私模式关闭磁盘保存则durable=false且会话内可恢复，不能仍展示“重启后可恢复”。磁盘满时停止接收新大图，手机保留未同步草稿；不能先清空手机再发现磁盘写失败。

电脑详情编辑文字会创建desktop分支修订并暂停手机覆盖，显示“手机有更新”。首版不做复杂协同算法：用户显式保留电脑版/采用手机版。画布仅手机编辑，避免两端多主冲突。编辑上次内容是新draft_id，不与旧版本共享清空事件。

## 7. 有边界的服务接口

CaptureService只执行枚举过的scope ID，不接受网络传入任意Win32句柄。
DeliveryService只收Bundle+Intent，不收任意按键序列/脚本/鼠标坐标。
FocusAdapter只返回VERIFIED_COMPOSER/VERIFIED_TEXT/UNSUPPORTED/UNKNOWN，不用“概率0.9”偷过验证。
HistoryService明确区分copy_to_new_draft、replay_bundle、delete，不以“恢复”含混三种副作用。
ByokService只处理用户这次选择的文字，不读取截图/历史/窗口内容；网络出口只允许已确认配置的endpoint。

# 05 · 安全、轻量预算、故障与迁移

## 1. 信任边界：不能把局域网说成自动安全

本工具可能接触私密截图、工作代码和输入内容。手机输入法自身可能使用其云端服务，本应用“不上传音频”不能等同“整个语音过程不走云”。本应用默认不自动向模型发送图片或正文，只有可选手动BYOK文字纠错另有网络出口。

继承现有HTTP局域网方式可作为**可信私人局域网模式**，但必须在第一次配对清楚提示：未加密传输可能被同网络攻击者窃听/篡改，配对不能解决网络窃听。公共Wi-Fi、跨公网或敏感材料场景不得以此模式宣传安全。HTTPS/WSS为后续安全连接配置方向；不要求第一版自行发明端到端加密协议，也不指导用户关闭浏览器证书校验。[S11]

公网隧道、路由器端口转发默认不支持；绑定0.0.0.0也不意味着允许公网来源。按所选局域网接口提供地址与访问策略，拒绝未授权Origin/Host和非预期网络来源。只有本地127.0.0.1设置界面不需要手机功能的广域访问。

## 2. 配对、截图、插入权限分开

扫码携带一次性高熵配对挑战，2分钟失效，一次成功即作废；电脑显示新设备请求供确认。记住设备可明确选择30天，默认本会话8小时。设备凭据存手机受限存储、可撤销；HTTP环境下仍有窃听风险，不能把它叫强网络安全。

设备权限分别为草稿/图像同步、手机发起截图、手机发起插入。手机远程插入只允许前台已验证目标；第一次启用说明风险并由电脑确认。手机截图首次选择显示器并授权；不允许网络消息传按键脚本、shell命令、文件路径或任意进程句柄。

WebSocket验证Origin、会话、消息schema和频率；令牌不写query/log。WS鉴权首帧有5s截止，在鉴权前不计为已连接设备、不收正文。HTTP上传需要同设备授权，禁止通配CORS；Cookie路线须加CSRF机制，不由实现者随意混搭。重连不恢复过期权限、不自动执行截图或插入。[S11]

## 3. 图片和隐私

导出只发送处理后的扁平化像素；编辑源图/图层默认不交给Agent。不同时附原图，尤其裁剪/遮挡后。遮挡必须是实心像素覆盖，导出测试通过解码结果检查被遮区域；不宣称普通荧光笔、马赛克或模糊等价不可恢复脱敏。

手机本地图像可被浏览器清理；用IndexedDB存草稿并显示保存状态。电脑近期图片/文本建议以系统凭据库保护的应用数据密钥进行本地加密存储；密钥库不可用则默认会话内存模式，并明确提醒重启不可恢复，不能悄悄把Key写进JSON。不得将密钥随可分享诊断包/ZIP导出。

删除仅承诺移除本应用记录及其无引用文件；无法保证SSD/备份/系统剪贴板历史/目标应用副本的法证擦除。剪贴板同步/历史可能被操作系统或第三方收集，首次引导给予说明。

## 4. BYOK和术语只保留一个旁路

默认没有自动模型请求。设置仅provider/base URL/key/model和“测试”；高级参数折叠。Key存在系统凭据库，不到手机、不入截图、不写日志。更换endpoint主机先清空Key关联或明确重新授权，禁止带旧Key到新域名。

只支持经过适配的Chat Completions兼容路径作为首批范围；“兼容”不等于所有厂商都接受相同temperature/response格式。测试错误区分DNS/TLS/401/403/404/429/超时/格式；不凭错误猜用户余额。请求总预算8s，失败保留原文且插入从未被禁用。

词库：`O PU S→Opus`由用户确认后可本地规则；`Midjourney→Image2`因语义冲突默认仅提示。语音输入法给的文本才是实际输入，无法靠后处理可靠还原原始录音。接受一次不等于永久记录；只在“记住改法”动作后存词条。代码/URL/路径等保护区默认不自动改写。

AI响应绑定draft_id/epoch/revision/hash；期间改稿、插入或切换稿件则旧响应不能应用。只显示局部差异并逐条采纳，不全稿覆盖。后台学习队列不自动迁移运行。

## 5. 轻量性能预算（均是目标，必须测，不是现状）

| 场景 | 目标 | 测量方法/不通过怎么处理 |
|---|---|---|
| 电脑空闲 | 桌面可见浮窗0；CPU中位≤0.3%、P95≤1%（任务管理器式总CPU归一化）；Private bytes≤180MiB目标、超过250MiB需阻止扩大 | 普通4核以上16GB机器，候选包预热后采样10分钟，记录硬件/电源模式/系统版本 |
| GUI唤醒 | 文字到达至首次HUD绘制P95≤100ms | 本机monotonic打点；原生记录，不含输入法识别时长 |
| 局域网文本同步 | 页面input事件至电脑接收并展示P95≤150ms目标 | 两端时钟不同不得直接相减；用关联ACK往返和校准误差分开记录 |
| 绘画反馈 | 单笔响应目标≤32ms P95；60Hz下尽量稳定，连续慢帧有记录 | 390×844手机、2MP图、200笔；桌面浏览器模拟不能替代手机 |
| 导出/上传 | 常见2560长边图导出≤1s目标；慢设备有进度/取消 | 本地导出与网络耗时分开，不能把等待伪装为卡死 |
| 纯文插入 | 目标通过后到发键P95≤150ms，不含用户释放修饰键 | 独立观测回执，不把文字确实进入目标计为无证据完成 |
| 包体 | Windows便携ZIP≤150MiB目标 | 实际锁依赖后测；不承诺PySide6一定达标，禁打包WebEngine/开发工具 |
| 网页资源 | 输入首屏JS gzip≤150KiB目标，画布按需加载≤500KiB目标 | 构建统计；首次纯语音不加载整个编辑器 |
| 稳定性 | 200轮图文链路、连续2小时使用，无丢稿/错误清理/双重投递 | 保存每轮状态和失败；非零错误不靠平均值掩盖 |

隐藏时停止动画/逐帧渲染；网络保持合理心跳，不轮询截图；截图按需，不常驻屏幕帧；一次只解码当前图并缩略其他图片。性能不通过先剖析和裁剪依赖，不直接再换一整套框架。

## 6. 出包与迁移

候选版使用独立配置目录，例如用户应用数据下DoubaoTypeless/preview-v3；不要与日用v0.4.2同端口/同热键同时抢资源。检测旧进程，提示退出或临时禁用候选热键，不杀旧进程。

迁移读取旧config.json/dictionary/历史，先脱敏预览再确认；保留旧文件原样、备份和迁移版本号。Key迁入凭据库成功才清理新JSON里的Key，绝不删除旧用户备份而不告知。旧图片不存在时不要伪造新记录。后台learn开关迁移为停用归档，不能自动耗费旧Key。

候选Windows便携包单独打包，由Windows runner构建；Linux上的Python测试不能生成经过Windows验收的EXE，PyInstaller不是跨平台交叉编译器。[S12] 本轮不覆盖稳定Release、不推v*标签触发现有直接发布流程。

构建应先npm ci + 前端测试/构建，再Python测试/静态检查，再PyInstaller onedir；Qt资源、网页资源、图标、许可证、锁文件和版本信息纳入制品。上传workflow artifact作为候选，不把“打包成功”标为运行验收。最终至少干净Windows机器启动、真实手机扫码、截屏、标注、先图后文、错焦点恢复、重启召回通过。

回退：退出候选，重新启动原稳定版；旧数据未被原地写坏。候选迁移失败能重复尝试且不会复写坏数据。所有公开发布需用户明确授权；本方案不授权开发模型自动merge/tag/release。

# 07 · 验收、证据和质量门槛

## 产品验收总表

`fixtures/acceptance.json` 包含 96 条逐项产品验收：每条有前置条件、步骤、可观察结果、执行层级、严重性、状态和证据数组。初始全部 **NOT_RUN**。本轮设计包的HTML原型测试与文档检查独立记录，不能改动此表为PASS。

## 状态定义

NOT_RUN=未执行；PASS=在记录的环境/固定提交中达到期望；FAIL=已执行但不满足；BLOCKED_NATIVE=缺Windows/真实手机/目标版本/密钥等；DEFERRED=仅已明确后置的新平台/隧道，不用于逃避R01–R10。

P0为数据丢失、错目标/重复插入、鉴权绕过、私密源图泄漏、空闲常驻等核心约束。任何P0未通过不得成为日用替换候选。P1缺项需用户明确接受，不能悄悄改规格。

## 必要测试层级

纯函数：草稿版本、Bundle冻结、图序哈希、Intent幂等、清空版本比较、恢复策略、过期AI。
协议集成：aiohttp随机回环端口、乱序重连、缺块上传、鉴权、大小/频率限制、事务失败。
手机浏览器：布局与编辑操作自动化，加真实输入法composition录制回放；模拟浏览器不能替代输入法、两指、键盘。
Windows：非激活窗口、修饰键释放、剪贴板真实图像、多应用焦点、权限、截图DPI。
端到端：真实手机准备图文→真实Cursor→人工看附件像素/文字→焦点错误召回；软件版本记录在证据里。

## 5. 选型决定记录

ADR-01：保留Python核心，不全量换语言。桌面Widgets轻表面，手机才承担画布；收益是职责清晰、减少栈，代价是两种UI测试与Qt依赖体积，G0实测决定是否扩大。

ADR-02：有限画布+可编辑对象，非整张位图不可逆涂改；支持修订和清晰导出，代价是坐标/撤销/多指要认真实现。

ADR-03：桌面热键是最低摩擦且最明确的目标授权；手机按钮有验证门槛，不自动抢最近窗口。避免把“无感”解释为允许向任何前台界面注入。

ADR-04：不承诺任意Agent一键图文。先做用户最常用Cursor版本验证，再按适配器扩展；泛化失败不危害文字链路。

ADR-05：暂不引入隧道/协同/无限白板。安全配对与恢复是当前图文功能本身的必要基础，不能后置。

# 10 · 逐控件、授权和错误状态设计补充

以下是实现规格，不是原型完成清单。状态板可以用于截图比对；真实原生窗口仍须在100%/150%/200%缩放验证。

## A. 桌面浮窗

纯文字HUD宽360高88，左右内边距14，上下12。顶行18高：6px状态点、13px状态文案、更多按钮28×28；正文最多两行，行高18；右侧“插入”72×32并显示Alt+I提示。插入按钮在数据缺失/重复动作时禁用；正文接收不等待AI。图片HUD增44px附件行，最多3个44×32缩略图及+N；缩略图不是图片编辑入口，点开详情查看即可。

活动条252×44，只有状态文案、图片数和更多。手机持续画图期间不能扩大到预览全文。系统空闲既无空壳也无悬浮图标。HUD显示后不在任务栏/Alt+Tab新增业务窗口，不改变外部光标；设置和详情可以是正常用户主动窗口。

警告最多两行：“请点电脑的输入框，再按 Alt+Shift+I”；不可只显示红点或英文异常。没有用户操作8秒后隐藏，手机保留错误。一次错误不循环弹出；再次出现只来自新的明确操作或新编辑活动。

## B. 图文详情420×320

顶栏44：标题“这份图文”、创建时间、关闭。缩略图区60高可横滚；正文区填充剩余高度，16px文字，保留换行可编辑。底栏48：插入、更多；更多含复制文字、复制选中图片、复制为新稿、删除这条记录。最小宽360、高280，默认最大自动高度480，长文内滚动不扩大窗口。

当前稿与上次快照分别显示“正在编辑”和“上次尝试”，不默认用新稿替换上次。编辑历史记录点“编辑为新稿”，确认后新建Draft；旧记录保持只读。删除记录只删除本应用保存内容，不撤销已经贴到外部输入框的内容。

## C. 手机配对和截图授权

手机未连接页不是空白报错：标题“连接你的电脑”，主说明“先在电脑托盘打开连接，扫码后确认这台手机”；已有连接失效时保留本地草稿并提供重新配对。凭据错误不得丢草稿。无有效二维码或地址时不画一个假二维码。

电脑首次配对窗440×360，展示设备请求、时限和网络模式警告。按钮“允许本次连接”“拒绝”；可选“记住30天”默认不选。允许同步不等于允许截图和远程插入。

首次手机截图触发电脑授权窗440×320：标题“允许手机截取这块屏幕？”，下拉显示器名/分辨率，本次预览来自明确请求，说明“只在手机点截图时截取，不持续共享”。按钮“允许一次”“本次会话允许”“拒绝”；默认为仅本次，不替用户自动选持续。返回手机显示截取中，15秒到期结束本次请求，不在用户几分钟后解锁时补截。

截图范围选择手机底部抽屉：最近使用显示器在前；其他已授权显示器；“电脑选择区域”仅唤起明确截图选择操作，不能绕过权限。支持断连返回后继续当前图文，不强制回到首次引导。

## D. 手机单页细节

上方连接区域52高；附件高度100左右，最多6张；单张102宽，点击进入编辑。删除命中区44×44，视觉圆20，尽量置于角外叠层，不能挡图内重要区域。附件更多含左移/右移/删除/角色，拖拽并不是唯一排序方式。

主输入框字体16或17px，行高1.75。没有图时输入框自然填充，无巨大占位Logo。键盘出现后缩短输入可视区，底部动作随visualViewport顶到键盘上方；软键盘隐藏后恢复。Composer不会因为每一条同步回执重设textarea.value/selectionStart；更不能中断输入法组词。

单主按钮48高，正文“插入电脑”。按下150ms内反馈准备状态，不要用户以为没响应连点。图片未全部准备好时按钮可启动等待，但从按下瞬间冻结文字、图片顺序和渲染版本；用户后续内容进入下一稿。无目标时不将按钮永远置灰，显示可重试动作，另可用电脑Alt+Shift+I完成。

## E. 手机标注工具状态

工具常显每个至少48宽×44高，选中用浅色底+图标色+标签共同区分。工具更多作为第二行/底部抽屉，不直接覆盖正在画的画布内容；开启时重新适配可视区域但不修改文档坐标。选色、粗细仅影响新笔或选中对象。画笔尺寸3档，完整拖条可后续。

裁剪底部临时动作只有“取消”“应用”；另有比例行“自由/原图/1:1/16:9”和全图恢复。取消回到进入裁剪前状态；应用后仍在编辑器；顶栏完成才回Composer。手柄44命中区优先于绘画，角点越界限制到源图；左右拖反交换选框方向，不产生负宽度。

旋转90°同时变换底图、裁剪矩形、所有标注坐标与文字基线，作为一次Undo事务；不得只旋转底图而标注留原位。插入参考图是白板对象，有边界与缩放；导出以本次场景为准，不把被删的参考图另附出去。

编号注释存为asset_id+marker_id，不只存“图1”。编号删除后其他编号默认不重新编号，避免语音描述失效；用户主动“整理编号”要预览并同步改绑定说明。手写小字不自动转文本；建议编号+语音描述，不强迫用户写字。

## F. 恢复抽屉

标题“找回上次图文”，显示时间、图数、文字首两行；缩略图可横滚。显示结果描述而不是技术字段：

|结果|主提示|可见动作|
|---|---|---|
|NO_STEPS|还没贴入任何内容|选中电脑输入框后完整重试；取消|
|图已确认、文字未执行|图片已放入，文字还没放入|只补文字；重新贴整份；取消|
|UNKNOWN|无法确认图片是否已贴入|已清空/换新输入框，完整重贴；只贴文字；取消|
|CONFIRMED|这份之前已经放入过，重贴可能重复|完整重贴（确认）；仅文字；取消|
|资产失效|上次图片已清理，无法完整重贴|查看尚存文字；关闭，不假装完整恢复|

任何“只贴文字”动作均展示文字预览；如果目标已换，说明不会自动把图补到新输入框。完整重贴按钮文案内包含已清空/新输入框条件，不背后清空目标。最近列表点一条只预览；点击列表不能立即重发。

## G. 低频设置 / BYOK

设置宽560高600，顶栏“设置”+关闭；内容垂直滚动、折叠分组，不设仪表盘。每组标题44，表单标签13、控件高40、字段间距12。保存失败保留所填值，Key以点遮掩，显示Key必须明确点按，失焦再次遮掩。

连接设备：电脑地址、扫码、设备列表和撤销；撤销二次确认后立即断开现有会话。快捷键：4个录制按钮、恢复默认、冲突解释；旧Alt+Shift+I功能迁移说明只显示一次。截图：允许范围、当前设备、清除授权。最近图文：保存开关、24小时时限、清理全部（确认）、当前占用。

AI组默认收起并标“可选”。展开为：手动文字纠错开关；兼容服务商/自定义；Base URL；API Key；Model；“测试连接”；错误区域。开关不代表每句自动请求。用户编辑endpoint主机先显示“更换服务地址后，需重新授权密钥”；取消保留旧主机，不把Key直接送给新站点。测试只发短固定文本，不带当前草稿。

术语入口放AI组旁的独立“常用改法”，说明本地规则无Key可用；正确写法/常见误识/仅提示或自动/作用范围各一个控件。默认“仅提示”；删除和禁用可撤销。原例Midjourney→Image2不预置自动规则。

## H. 错误文案和恢复动作

|业务码|对用户的文案|动作|
|NEEDS_TARGET|请先点电脑上的目标输入框|已选中，重试；电脑热键|
|TARGET_CHANGED|输入位置变了，后续内容已停止|查看进度 / 召回|
|IMAGE_UNCONFIRMED|图片已尝试贴入，但无法确认接收|确认后继续 / 完整重贴|
|CLIPBOARD_BUSY|剪贴板暂时被占用，图文已保留|重试 / 手动复制|
|CLIPBOARD_CHANGED|检测到你复制了其他内容，已暂停|继续前重新确认|
|ASSET_MISSING|有图片尚未完整传到电脑|补传 / 保留草稿|
|UNSUPPORTED_IMAGE|暂不支持这类图片，请换PNG/JPEG/WebP|重新选择|
|CAPTURE_DENIED|这台手机还没有截图权限|在电脑批准 / 返回|
|LOCKED|电脑已锁定，未执行操作|解锁后重新点击，不自动补执行|
|STORAGE_FULL|本地空间不足，新图片未保存|清理最近记录 / 导出草稿|
|API_TIMEOUT|AI响应超时，原文仍可插入|重试AI / 继续使用原文|

不得展示含Key、绝对私密路径、原文/窗口标题的异常堆栈；诊断详情使用错误码、阶段、耗时、字节数。原生API错误仅保存在脱敏诊断字段。
