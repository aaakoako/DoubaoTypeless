# 直接开发：运行日志与异常取证

这不是新产品方案，也不是 RELEASE_READY 声明。继续使用 MASTER_PLAN。

## 本提交实现

- `ui/filelog.py`：文件先落地，控制台只是可选镜像；断管、无控制台、日志目录不可写不再把异常传回输入操作。单实例线程锁、大小上限与轮换。
- `runtime_diagnostics.py`：记录进程 PID、真实可执行文件路径、启动/退出原因及退出码；接收未处理的 Python 主线程/普通工作线程异常；本地记录异常类型、错误号、文件/函数/行号，不记录异常消息、源码行或局部变量。
- `tools/run_v3.py`：正式 PyInstaller 入口先安装取证，再导入应用。不是只新增一个没人调用的工具。
- `faulthandler`：此前没有故障处理器时启用进程独立文件；句柄保持到处理器关闭。不捕获完整内存、不上传、不修改 WER 或系统注册表。已有处理器不抢占。

文件位于预览数据目录的 `logs/runtime.log` 和 `logs/fault-<PID>-<run>.log`。
现有 `logs/v3.log` 继续存在；日志写失败可从 `FileLogger.last_error` 观察，不递归记日志。
故障栈可能包含本机源码路径，分享前审阅。普通工作线程异常仍按原语义停止该线程；此提交不会自动重启、重试粘贴或把非零退出改成成功。
