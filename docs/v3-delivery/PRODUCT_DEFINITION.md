# DoubaoTypeless V3：产品交付定义

更新：2026-09-19。

**交付目标：重构现有 Windows 图形客户端，同时增加手机图文工作区。不是把原有客户端替换为命令行服务，也不是只交付手机网页。**

本文件澄清产品最终形态与正式入口，纠正“桌面不是主界面/只是投递器”容易引起的过度精简。原 V3 的安全、图文顺序、不可变快照、错误恢复、原文保护及手机画布规格继续有效。它不是新的一轮框架重写，不重新编号原有全部任务，也不授权合并、打标签或公开发布。

## 1. 本次核对到的事实与边界

远端 `v3/00-baseline` 在本次查询时指向 `55d03cc965652c3a8e019174d9d8463575446acc`。其 `docs/release/checksums.txt` 声明包的源提交为 `5f122b07ee1e438fb118e5b516e0d5119c13ca67`，EXE SHA-256 为 `3ae9173fcf5ab79a8ecaa990458555f4775527f1dfdb7f5f147f3bbf957f60d4`，与用户提供的文字记录一致。

这只是记录相符。本轮没有取得本地 EXE 字节，没有重新计算包哈希，没有运行该 Windows 包，也没有重新验收手机链路。

在声明的源提交中：

- `packaging/v3_preview.spec` 的 `EXE` 使用 `console=True`。
- `app.py::start` 把手机地址、配对码打印到控制台并写入 `pair.txt`。
- `app.py::main` 创建 HUD、热键和后台服务；此入口没有装配桌面欢迎/设置窗口、托盘入口或首次引导。
- `ui/hud.py` 是带状态文字、正文标签和插入按钮的按需窗口；不是完整的设置、审阅与历史客户端。

远端现有 `static/pc.html` 是浏览器设置页，含设备授权、热键和 BYOK；不能说完全没有电脑侧界面代码。但网页可访问，不等于双击 EXE 后就有正常的客户端体验。S4 记录中的 `pc_reachable/settings_reachable` 也不能替代该体验。

**当前应理解为工程预览，桌面产品交付未闭合；不能把后续工作归结为“只剩用户验收”。**

## 2. 产品由什么组成

| 部分 | 用户承担的动作 | 产品必须提供什么 |
|---|---|---|
| Windows 图形客户端 | 安装/解压后双击，连接手机，修改设置，必要时审阅与重试 | 正常图形入口、托盘、引导、连接、可编辑详情、历史、错误与退出 |
| 手机图文工作区 | 说话、选图、截图、指绘、裁剪、补充说明 | 一个 Composer，附件编辑器与轻量白板，接收状态与可恢复草稿 |
| 两端连接与投递 | 显式按插入按钮或快捷键 | 已处理图片先、文字后；不发送 Enter；错误目标不盲贴，上次内容可召回 |

精简的是操作和干扰，不是删掉必需界面。手机适合长段语音和指绘；电脑适合连接管理、快速改字、查看完整图文和定位投递问题。用户不应被迫所有操作都回手机完成。

## 3. 打开、隐藏、重新打开与退出

**“不常驻”约束的是自动出现的浮窗，不禁止用户主动打开正常客户端窗口。**

| 入口/状态 | 行为 |
|---|---|
| 首次双击 EXE | 显示小型欢迎/连接窗口，带二维码和可读的操作提示；不用命令行 |
| 手动启动，已完成引导 | 打开连接/常用设置窗口，清楚反馈程序已启动；用户可关闭到托盘 |
| 已经运行，再双击 EXE | 唤起既有客户端窗口，不启动第二个后台实例、不静默报错退出 |
| 用户开启自启动，随后随系统登录 | 已配置时静默到托盘，不打开普通窗口或输入浮窗 |
| 未开始输入、只是保持连接 | 无输入浮窗、无悬浮球；用户主动打开的设置窗口不自行消失 |
| 手机有真实文字或图片编辑活动 | 非激活小浮窗短暂出现；心跳不唤醒 |
| 关闭连接/设置窗口 | 隐藏窗口，保持用户已开启的连接；首次说明仍在托盘运行 |
| 托盘“退出” | 真正停止桥接、热键和后台任务，安全结束进程；不是仅隐藏窗口 |
| 启动失败 | 显示可读错误、重试和诊断入口；不得静默变成无界面的后台进程 |

日志进入有大小限制的文件。用户从“帮助与诊断”查看，不需要控制台常驻。开发诊断包可以有控制台，但与交付给普通用户的图形包分开标识。

## 4. Windows 客户端的具体呈现

### 4.1 小型连接与设置窗口

建议沿用约 `560×600` 逻辑像素的低频窗口，不做 980×720 常驻管理台。可按屏幕工作区缩放/滚动，不能让小屏设备访问不到底部操作。

```text
DoubaoTypeless                                  —  ×

连接手机       常用设置       最近内容

让手机成为更顺手的输入工具。

┌─────────────────────────────────────────┐
│   [二维码]    用手机浏览器打开并连接       │
│               手机与电脑连接同一局域网    │
│               [复制地址]  [连接帮助]      │
└─────────────────────────────────────────┘

手机 A 请求连接
[允许连接]  [拒绝]
截图/插入权限在适当时机另行说明与批准。

连好以后：手机说话，电脑 Alt+I 插入。
不配模型 Key 也能使用文字、图片和白板。

[开始使用，收起窗口]                 帮助与诊断
```

连接后二维码区域收起，换成设备名称、连接状态、重新配对/撤销入口。二维码不得永久暴露动作权限；可记住设备，但必须是用户明确选择。截图权限细分授权范围，不能默认整机持续共享。

常用设置包含外观、快捷键、自启动、连接与截图权限、历史保留、可选 AI。AI 表单必须实际可配置 Base URL、Key、模型 ID 并测试连接；高级参数折叠。不能让用户改 JSON，也不能把“无需 Key”的说明当作 BYOK 已完成。

最近内容显示缩略图、首行正文、时间和上次状态。点击可预览、复制、恢复或重试；“恢复为当前新稿”和“重投上次快照”区分清楚。不做项目管理、文件夹或标签体系。

### 4.2 输入浮窗：自动出现，不抢焦点

默认沿用纯文字约 `360×88`、带图约 `360×132`，不随长文不断增高。底部/用户记住的位置锚定在工作区内。

```text
手机输入中                                      …
把图①中的按钮移到右侧，其他内容保持不变。

[① 处理图] [② 草图]             [展开] [插入 Alt+I]
```

没有图片就没有附件占位条。没有 AI 候选就不展示候选区域。活动停止约 6 秒后隐藏；隐藏不是删除草稿。结果确认后约 900 毫秒收起；失败短暂提示，完整内容在手机与详情中保留。

自动浮窗不能夺走 IDE 焦点；但用户点击“展开/编辑”是主动打开可交互界面，两者不混用。用户正在编辑、选择文字或处理弹窗时，不按活动计时自动隐藏。

### 4.3 展开审阅：保留旧客户端快速改字的价值

默认约 `420×320`，可调整大小。显示完整文字、图片缩略图及图序，支持修改文字、复制、手动 AI 辅助、插入和查看上次图文。

不能要求用户为了改一个错字必须回手机；也不在电脑上重复建设一套完整绘图软件。查看大图及“继续在手机标注”即可满足本轮分工。

电脑手动改稿期间，手机更新不能静默覆盖电脑文字。应暂存手机新版本并提示“手机有更新”，让用户选择采用手机版还是保留电脑稿。任何插入都冻结明确的一版，不能边贴边混入新内容。

### 4.4 托盘是可发现的入口，不是唯一隐藏的操作说明

菜单保持简单：打开客户端、当前图文、召回上次、截图给手机、暂停连接、退出。可以通过子菜单收纳低频项；状态和权限在客户端窗口里解释，不靠颜色猜。

暂停连接不删除稿件，不在恢复连接后补执行旧截图或插入命令。

### 4.5 错误、重试必须有实际界面

| 状态 | 具体文案/动作 |
|---|---|
| 找不到目标 | “请点电脑上的目标输入框，再重试。”保留本次图文 |
| 图片已进入、文字未进入 | 同目标且有证据时提供“只补文字” |
| 上次结果不确定 | 展示“完整重贴 / 只贴文字 / 取消”，不静默选择完整重贴 |
| 无上次记录 | 清楚提示，没有自动拿当前稿冒充上次 |
| 已发送完又要求重试 | 警告重复风险，用户确认后新建投递操作 |
| 图片缺失/清理 | 明确哪张不可恢复，不能将残缺内容伪装成原图文 |

“已发粘贴按键”和“目标已收到”必须区分。正常支持的主目标应实现一键图文；确认不了的目标可以提供安全降级，但不能把手动降级包装为主目标一键已经完成。

## 5. 手机工作区与客户端如何配合

手机保持一个 Composer，不改成多个管理标签。上方连接与最近记录，中间附件和普通文本输入框，下方是“截电脑 / 相册 / 白板”和“插入电脑”。继续调用用户自己的手机输入法，不自研网页 ASR。

截图、相册、白板进入同一个编辑器。第一轮完整范围保留圆头笔、记号笔、荧光笔、箭头、线、框、椭圆、编号、文字、撤销重做、选择移动、快速裁剪、实心遮挡和基础线框组合。有限画布，不做专业图层管理或无限协作白板。

完成后回到同一份图文；附件点开可继续编辑，不能只有一次性导出。编辑中可补充语音说明。成品按稳定场景坐标导出，不把手机缩放后的屏幕截图当最终图片。

源截图保留用于本机编辑，投递默认只包含用户选定的已处理输出。不偷偷添加被裁掉的原图，不附带隐藏图层。多图顺序就是后续进入 Composer 的顺序。

两端分工并不意味着两个互相独立的产品：设备名、当前稿、图片顺序、接收状态和上次记录必须一致。电脑改字/手机继续说话、电脑截图/手机标注、手机插入/电脑选择目标，都要有清楚的状态交接。

## 6. 普通用户必须能走完的流程

### A. 第一次使用

下载完整 Windows 包 → 解压或安装 → 双击 → 看到图形欢迎窗口 → 扫码/复制地址 → 批准设备 → 输入测试 → 练习插入 → 收起到托盘。

不安装 Python、Node、ADB；不执行启动命令、不改环境变量、不打开配置 JSON、不从日志中寻找配对码。上述工具可以用于开发测试，不应成为普通使用的前置条件。

本机练习框用于引导及受控测试，不代表真实 Cursor 已兼容。

### B. 日常纯文字

电脑正常工作 → 手机语音输入 → 浮窗短暂出现不抢焦点 → 必要时展开改一个词 → 点好目标/按热键 → 文字进入输入框 → 浮窗隐藏。

不必查看仪表盘，也不必先等 AI。真实原文完整保留，包括换行和缩进。

### C. 图文表达

手机点截电脑 → 获取已批准范围 → 手指裁剪圈画 → 语音补充说明 → 需要时添加白板草图 → 插入电脑 → 在支持目标里先图后文 → 用户自己发送给 Agent。

### D. 错误恢复

第一次目标错误 → 内容还在 → 点正确 Composer → 召回上次 → 根据已完成步骤安全补贴或重跑 → 当前新稿不丢。

### E. 维护

从托盘打开设置 → 改快捷键/外观/BYOK/权限 → 图形反馈保存结果 → 关闭设置回到无窗口。再双击 EXE 能重新打开，不创建重复服务。

## 7. 外观与手感

延续浅色纸面、深色正文、克制青绿色主动作，深色主题做对应层级。系统字体，不分发系统字体文件。桌面低频窗口用正常标题栏/清晰关闭按钮；浮窗才使用克制的无边框设计。

统一 4/8/12/16/24 间距和图标；手机主要触控命中范围至少 44×44；主动作文字清楚，不能用“设/近/撤/重”替代所有完整标签而不提供解释。长文不把小窗撑满屏，缩略图不抢正文空间，加载与报错不挤掉主按钮。

动画短、可关闭；空闲没有循环动画或无意义刷新。不以追逐“最新框架”作为性能优化。用当前机器实测启动、空闲资源、图像操作和连续使用；低于包体预算不等于界面已经好用。

## 8. 需要开发成什么，而不是再堆哪些文件

继续现有 Python + PySide6 Widgets 桌面、TypeScript + Vite + Konva 手机、aiohttp/SQLite 基础，不同时推倒重写框架。

将桌面生命周期单独组织起来：

- `DesktopApplication`：QApplication、实例唤起、托盘、启动与退出。
- `ConnectionWindow`：首次欢迎、二维码、设备/权限和连接帮助。
- `SettingsWindow`：真实常用设置、BYOK、历史保留与诊断。
- `ReviewPanel`：可编辑图文详情、图序、手动修正和插入。
- `RecoveryDialog`：真正等待用户选择，不只返回 `ask` 字符串。
- `HudWindow`：自动显示/隐藏和简短状态，不承包所有客户端职责。

这些是职责建议，不要求为了同名而机械创建一堆类。桌面 UI 调用同一套应用服务；通过主线程信号接收状态。手机页面通过协议访问同样的业务状态。不要另写只给桌面演示用的假后端，不让浏览器设置和原生设置维护两份配置。

`pc.html` 可以作为明确标记的开发诊断入口保留；正常用户不应依赖它完成客户端配置。今后若要改成浏览器控制台产品，必须作为显式产品决策另行讨论，不能以“无 WebEngine”为理由默默替换。

用户候选包使用无控制台构建，并配套 GUI 错误处理和文件日志。仅把 `console=True` 改成 `False` 不算修复：那可能只是把唯一可见的提示藏掉。GUI 初始化失败要明确报错，不允许无界面无限等待。

## 9. 开发推进与交付要求

当前目标仍是完整 V3，不是只补一个漂亮空壳。

第一优先：补齐桌面产品入口和生命周期。下次可展示的产物必须是实际 Windows 包，从双击打开、配对窗口、托盘、设置、详情到退出都可操作。没有手机也能验证空状态、设置、错误、托盘和重复启动；开发者不应拿缺 Android 为这些缺项开脱。

随后将同一个产品入口依次接通纯文字、单图标注、多图白板、恢复、BYOK与完整设置。既有协议和存储中确认可复用的部分保留，已知安全缺陷优先修复后再接真实设备。

每个阶段留小提交、可续跑记录，但完成当前切片后继续总目标，不要求用户逐卡调度。必要的独立评审和缺设备验证可阻塞相应放行，不能变成“所有工作都交给用户验收”。

### 最小展示材料

开发者交下一个产品包时，用同一份包录制桌面启动到退出过程，并给出原生截图；不能用 HTML 原型冒充。文字和图片链路必须由实际页面产生请求，不在测试脚本里补生产页面没发送的字段。

需明确展示：首次启动；未连接；连接和批准；输入浮窗；展开编辑；设置；最近内容/恢复；关闭到托盘；二次打开；真正退出。该清单是原有界面要求的可观察化，不是新增可有可无的功能。

## 10. 何时可以说“只剩真机与独立复核”

只有下列三层同时分清楚，才允许使用该说法：

1. **客户端产品形态已完成**：正式 EXE 的图形入口、托盘、设置、详情、错误、退出均可用，无需命令行。
2. **已实现的业务流程已从正式入口验证**：真实前端、真实后端与正确图片/文字；不是只测内部变量或样板目标。
3. **剩余项确实依赖缺失的设备/目标环境或独立审阅**：例如特定豆包输入法行为、真实手机双指手感、真实 Cursor 接收与最终试用。

若第 1 层没完成，叫桌面功能未完成；若第 2 层不满足，叫实现/集成未完成；不能统称 `WAITING` 或 `BLOCKED_NATIVE`。

普通用户、尤其首次启动用户，不需要填完审计表才有资格提出“没有界面”。首次打开无法发现和操作客户端，本身就是有效的产品问题。

## 11. 完整候选与发布边界

完整候选包含全部原定 V3 范围；macOS/Linux、公网隧道继续后置。一键图文必须在记录版本的首要目标环境中验证；其他目标的降级能力明确说明。

交付整个 onedir 目录或包含它的 ZIP，不能只交 EXE 的哈希而忽略依赖与前端资源。建立源码提交、构建输入、完整包校验值、实际测试对象之间的对应关系。包哈希回答“是哪份包”，不能回答“这份包是否成品”。

正式发布需安全与完整性回归、原生/真机主流程、独立复核、用户高频试用、版本说明、已知限制和回退途径。用户最后批准具体版本；开发者不能自签独立复核，但仍有义务完成界面与软件本身。空着审批单是正常边界，不是实现完成证明。

## 12. 可直接交给实现者的入口

```text
产品目标澄清：V3 = 重构后的 Windows 图形客户端 + 手机图文工作区。
不常驻不等于无客户端；手机是主要创作端，不代表桌面只有命令行和隐藏HUD。
```
